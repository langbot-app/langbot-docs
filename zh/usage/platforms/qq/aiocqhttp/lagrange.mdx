## 4.11 新版 OneBot 连接配置（onebot-v11）

新版标识为 `onebot-v11`；已保存的 `aiocqhttp-omni` 和 `aiocqhttp-eba` 作为兼容别名继续可用，旧版 `aiocqhttp` 不变。

本节适用于支持更多事件和 API 的 4.11 新版适配器。旧版 `aiocqhttp` 保留原实现、独立监听端口和原有配置，无需迁移。

默认选择 **反向 WS — 协议端连接 LangBot**。创建机器人，填写非空访问令牌并保存，然后复制“协议端连接地址”，填入协议端的 WebSocket 客户端配置，选择 **Universal**，并设置相同令牌。

地址形如 `wss://你的域名/bots/<bot_uuid>/onebot/v11/ws`，与管理界面共用主服务端口；本地可用 `ws://主机:5300/bots/<bot_uuid>/onebot/v11/ws`。容器内的 `127.0.0.1` 只指向当前容器；跨容器请使用服务名或可访问的域名。

也可选择 **正向 WS — LangBot 连接协议端**，在协议端启用同时提供事件与 API 的 WebSocket 服务端，在 LangBot 填写其 `ws://` 或 `wss://` 地址及相同令牌。该地址必须能从 LangBot 访问。连接中断后 LangBot 会自动重连。

两种模式均使用 `Authorization: Bearer <token>`。可填写预期机器人账号以拒绝其他账号。反向连接需要 `X-Self-ID` 和 `X-Client-Role: Universal`。暂不支持分离的 API/Event 连接或 HTTP 模式。

### 新版配置迁移

仅新版适配器不再使用 `host`、`port`：已使用新版的机器人需在协议端改填配置页的新地址，并补齐访问令牌。旧版机器人的 `host`、`port`、可选令牌和 `:2280/ws` 连接方式保持不变，不会自动切换到新版。旧截图只供安装参考，连接地址和字段以本节及当前界面为准。

反向代理需要支持 WebSocket Upgrade，使用公网 HTTPS 时连接地址应为 `wss://`。设置正确的公开 Webhook 前缀以生成外部可访问地址。云端入口必须按机器人所属 Workspace 路由到当前 placement 实例；普通随机负载均衡不能保证找到连接所有者。停用、删除或迁移机器人后旧连接会失效；协议端应自动重连。连接中断时不自动重放发送请求，以免重复发消息。

## Lagrange介绍

Lagrange 是一个 QQNT 协议逆向工程框架，轻便且相对稳定。通过 OneBot 11 协议接入，需选择使用`OneBot v11`作为适配器。

<Warning>
需要使用 NT QQ 与机器人交互，旧版QQ无法正常使用
</Warning>

## 部署步骤

以下仅提供 Windows 上的大致步骤，详细步骤或其他平台请参考 [Lagrange官方文档](https://lagrangedev.github.io/Lagrange.Doc/v1/Lagrange.OneBot/)

安装.NET 8运行时，[点击直达微软官网下载](https://dotnet.microsoft.com/zh-cn/download/dotnet/thank-you/runtime-desktop-8.0.4-windows-x64-installer)

### 尾声

解压你所下载的zip，打开到有Lagrange.OneBot.exe的目录，在此目录下打开cmd命令提示符，输入

```bash
.\Lagrange.OneBot
```

运行一次，如果输出了一个二维码，即可直接用机器人号扫码登录（若二维码显示不清楚，可以到lagrange的data目录下寻找图片文件）。  

若无法登录，请检查是否正常填写了lagrange配置文件appsettings.json中的签名地址 SignServerUrl ，签名地址请到lagrange文档中寻找。  

## 修改配置

需要配置 Lagrange 以让其连接上 LangBot，请编辑 Lagrange 的配置文件 appsettings.json，确保 Implementations 中的连接配置符合下图内容：

![配置连接](/images/zh/deploy/bots/qq/onebot/lagrange/config_lgr.png)

其中 Type 必须为 `ReverseWebSocket`;  
Host 为 LangBot 运行的主机 IP，若在同一主机上，可以写 `127.0.0.1`；   
Suffix 必须为 `/ws`；
