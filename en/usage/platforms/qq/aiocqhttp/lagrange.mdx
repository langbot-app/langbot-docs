## OneBot 4.11 new adapter settings (onebot-v11)

The new ID is `onebot-v11`. Saved `aiocqhttp-omni` and `aiocqhttp-eba` IDs remain supported aliases; legacy `aiocqhttp` is unchanged.

This section applies to the new 4.11 adapter with expanded events and APIs. The legacy `aiocqhttp` adapter retains its implementation, dedicated port and existing configuration; no migration is required.

The default is **Reverse WS — protocol endpoint connects to LangBot**. Create and save a bot with a non-empty access token. Copy the protocol endpoint connection URL into the endpoint's WebSocket client, select **Universal**, and configure the same token.

Use `wss://your-domain/bots/<bot_uuid>/onebot/v11/ws`, sharing the main service port, or locally `ws://host:5300/bots/<bot_uuid>/onebot/v11/ws`. Inside containers, localhost refers only to that container; use a reachable service name or domain.

Alternatively select **Forward WS — LangBot connects to protocol endpoint**. Enable the endpoint's Universal WebSocket server and enter its reachable `ws://` or `wss://` URL and matching token in LangBot. LangBot reconnects after disconnection.

Both modes use `Authorization: Bearer <token>`. Optionally pin the expected bot account. Reverse connections require `X-Self-ID` and `X-Client-Role: Universal`. Separate API/Event sockets and HTTP mode are not supported.

### Migrating new-adapter configuration

Only the new adapter stops using host/port. Bots already using the new adapter must update the endpoint URL and set a token. Legacy bots keep host/port, optional tokens and `:2280/ws`; they are not automatically switched to the new adapter. Old screenshots are installation references; use these instructions and the current UI for connection settings.

Your reverse proxy must support WebSocket Upgrade. Use wss with public HTTPS and configure the public Webhook prefix correctly. Cloud ingress must route each bot to its Workspace's current placement instance; random load balancing is insufficient. Disabling, deleting or relocating a bot invalidates its connection. The endpoint should reconnect. Pending sends are not replayed after disconnection to avoid duplicate messages.

## Lagrange Introduction

Lagrange is a QQNT protocol reverse engineering framework that is lightweight and relatively stable. Connect through the OneBot 11 protocol, you need to select `OneBot v11` as the adapter.

<Warning>
You need to use NT QQ to interact with the bot, old versions of QQ will not work properly
</Warning>

## Deployment Steps

The following only provides general steps for Windows, for detailed steps or other platforms, please refer to the [Lagrange official documentation](https://lagrangedev.github.io/Lagrange.Doc/v1/Lagrange.OneBot/)

### Environment Configuration

Install .NET 8 runtime, [Click here to go directly to Microsoft's official website to download](https://dotnet.microsoft.com/zh-cn/download/dotnet/thank-you/runtime-desktop-8.0.4-windows-x64-installer)

### Download the latest build from Github Actions

You need to log in to Github to download. If you don't need certain features, you can download from Release, see image 3

[Github Actions](https://github.com/KonataDev/Lagrange.Core/actions)  

Follow the images to download:

![Image 1](/images/zh/deploy/bots/qq/onebot/lagrange/dl_lgr_1.png)

![Image 2](/images/zh/deploy/bots/qq/onebot/lagrange/dl_lgr_2.png)

![Image 3](/images/zh/deploy/bots/qq/onebot/lagrange/dl_lgr_3.png)

### Final Steps

Extract the zip you downloaded, navigate to the directory containing Lagrange.OneBot.exe, open a cmd command prompt in this directory, and enter

```bash
.\Lagrange.OneBot
```

Run it once, if a QR code is output, you can directly scan it with the bot account to log in (if the QR code is not clear, you can look for the image file in the lagrange data directory).  

If you cannot log in, please check if you have correctly filled in the signature address SignServerUrl in the lagrange configuration file appsettings.json. Please look for the signature address in the lagrange documentation.  

## Modify Configuration

You need to configure Lagrange to connect to LangBot. Please edit Lagrange's configuration file appsettings.json and ensure that the connection configuration in Implementations matches the content in the image below:

![Configure Connection](/images/zh/deploy/bots/qq/onebot/lagrange/config_lgr.png)

The Type must be `ReverseWebSocket`;  
Host is the IP of the host running LangBot, if on the same host, you can write `127.0.0.1`;   
Suffix must be `/ws`;
