LangBot は利用状況の把握と信頼性の改善のため、設定された LangBot Space サービス（既定は `https://space.langbot.app`）にテレメトリを送信します。**既存の製品テレメトリと Beta 診断は別のデータストリームです。** 本ページは Core 4.11.0-beta.2 の診断スキーマ v1 を説明するもので、既存の製品分析設定を変更するものではありません。

## 既存の製品テレメトリ

有効な場合、既存のクエリ処理経路から次のデータが送信されることがあります。

| データ | 内容 |
|---|---|
| 識別子と環境 | `instance_id`、`workspace_uuid`、ランダムな `query_id`、バージョン、アダプターとランナーの種類 |
| クエリ統計 | モデル名、処理時間、タイムスタンプ、パイプラインプラグイン名 |
| 機能利用 | 呼び出し元別のツール呼び出し数、ツール呼び出しラウンド数、ナレッジベースと検索結果の件数、ナレッジエンジンプラグイン ID、サンドボックス実行/エラー数、有効化したスキル名、設定された MCP サーバー名 |
| エラー | 旧 `error` フィールドには、例外メッセージを含む生の traceback が入ることがあります |
| マネージド実行環境の活動 | マネージド SaaS クエリの `runtime_instance_id` はアイドルタイムアウトの活動更新に使用され、分析イベントレコードには保存されません |

機能カウンターは、ツールの引数/結果、検索テキスト、サンドボックスのコード/出力を意図的に含めません。**ただし、旧方式の例外テキストやユーザー定義のモデル・スキル・MCP 名には機密情報が含まれる可能性があります。新しい内容非収集の診断ルールは、この既存ストリームを無害化するものではありません。** 既存のテレメトリについて、ユーザーコンテンツを一切含まないとは保証できません。

アクティブなワークスペースは、起動直後とその後毎日ハートビートを送信します。デプロイ環境、データベース/ベクトルデータベースの種類、サンドボックス設定と可用性、有効なアダプターの種類、リソース数を含みますが、リソース内容や接続情報は含めません。

任意参加のアプリ内アンケートでは、アンケート ID、送信した回答、インスタンス ID、バージョン、完了/閉じた状態を送信します。回答はユーザーが提供するコンテンツであり、Beta 診断ではありません。

## Beta 診断 v1 — 4.11.0-beta.2

Beta 診断は**Beta 版のみで既定で有効**です。安定版、alpha 版、rc 版ではこの送信機能は有効にならず、今回のリリースでは安定版のオプトインも提供しません。追加の設定、同意ウィザード、必須のテスト手順はありません。収集はバックグラウンドで行い、キュー、バッチ、タイムアウト、再試行には上限があります。診断サービスが利用できなくても、通常の Bot 利用を妨げない設計です。キュー上限や通信障害により診断記録が失われることがあります。

診断対象の操作から、許可リストにある、業務コンテンツを含まないメタデータのみを記録します。

- Core/SDK/公開プラグインまたはランナーのバージョン、ビルド revision、デプロイ/環境の分類、対応・設定済み機能。
- 操作とイベントの分類、プロセッサーの種類、実行段階、観測された結果、回数と所要時間。
- 固定の理由コード、エラー分類、コード識別子から生成するフィンガープリント。**例外メッセージや生の traceback は使用しません。**
- 独立した `instance_id` と任意の `workspace_uuid`、および手順を関連付ける不透明な event/trace/span/run 識別子。インスタンス単位のイベントにはワークスペースがない場合があります。
- 生成、受信確認、再試行、破棄などの送信側の状態カウンター。

**これらは仮名化された識別子であり、匿名データではありません。** インスタンスとワークスペースは異なる識別軸で、互いの代わりにはなりません。識別子がアカウントやデプロイ環境と結び付く場合があります。「未認証の報告元」は「識別できない」という意味ではありません。

### Beta 診断記録に含めないもの

メッセージ、プロンプト、モデルの回答、生のプラットフォームイベント、ツール/API の引数や結果、フォーム値、ファイル/メディア内容、ファイル名やローカルパス、生の URL/クエリ文字列、認証情報、プラットフォームのユーザー/グループ ID、ユーザー定義のリソース名、生の例外や traceback は含めません。任意のテキストではなく、公開コンポーネント ID と固定の操作分類を使います。通信基盤は配信と不正利用防止のため送信元 IP を扱います。すべてのサービスアクセスログに IP が含まれないという保証ではありません。

診断は、観測された経路での互換性問題や回帰の発見に用います。クエリ利用量、リテンション/ファネル統計、アカウントの紐付け、マネージド環境のアイドルタイムアウト活動とは分離しています。プラットフォーム API がリクエストを受け付けても、ユーザーがメッセージを受信・閲覧したことの証明にはなりません。記録がない経路や未テストの経路を成功とはみなしません。

## 保存と保持期間

既定のサービスに送信されたデータは、LangBot Space のために運用されるサーバーに保存されます。管理者、テレメトリへのアクセスを明示的に許可されたメンバー、および認可されたサービス API クライアントは Beta 診断を閲覧できます。通常のワークスペースのメンバーであるだけでは、この権限は得られません。**サーバーの既定削除しきい値は診断の詳細が 30 日、集計データが 90 日**で、設定はこれらの期間を上限とします。しきい値に達した記録は削除対象となり、定期実行のワーカーが処理量を制限したバッチで削除します。処理の滞留やサービス停止により削除が遅れる場合があり、特定の時刻での削除を保証するものではありません。この期間は新しい診断ストリームにのみ適用され、既存の製品テレメトリ、アンケート、サービスログ、アカウント記録の保持規則を遡って変更しません。既存テレメトリは従来の製品分析の保持設定に従います。

オプトアウト設定が反映されると、以降の診断送信を停止し、ローカルの未送信診断記録を消去します。サーバーがすでに受信した記録は**削除されません**。過去のデータの削除は [hello@langbot.app](mailto:hello@langbot.app) または利用中の Space 管理者に依頼してください。有効なアカウントを持つ管理者と認可されたサービス API クライアントは、インスタンスと該当するワークスペースを指定して診断を削除できます。テレメトリの閲覧権限だけでは、削除やエラー状態の変更はできません。識別子は公開 Issue に載せず、非公開で共有してください。

## オプトアウト

Beta 診断のみを無効にするには、`data/config.yaml` の既存の `space` セクションで次を設定し、他の設定を保持したうえで LangBot を再起動します。

```yaml
space:
  disable_beta_diagnostics: true
```

クエリテレメトリ、ハートビート、アンケート、その他の製品分析設定は変更しません。

Beta 診断を含む Core テレメトリを無効にするには、マスタースイッチを設定して再起動します。

```yaml
space:
  disable_telemetry: true
```

マスタースイッチは Beta 設定より優先され、既存のクエリ/ハートビート送信とアンケート取得も無効にします。引用符付き文字列ではなく、YAML の真偽値（`true`/`false`）を使ってください。デプロイ環境で `SPACE__DISABLE_BETA_DIAGNOSTICS` または `SPACE__DISABLE_TELEMETRY` が設定されている場合、起動時に環境変数がファイルの設定を上書きします。これらも変更または削除してプロセスを再起動してください（コンテナの環境変数を変更する場合は再作成が必要です）。診断には `space.url` の設定も必要です。`4.11.0b2+local` のようなローカルバージョン識別子を持つビルドでは送信機能は有効になりません。Bot 自体は無効にならず、メッセージングプラットフォーム、プラグイン、モデル提供者、その他のオンラインサービスのプライバシー設定も変更しません。

## 任意の Beta テストチェックリスト — 4.11.0-beta.2 / v1

テスト用 Bot、テスト用ワークスペース、機密性のないサンプルデータを使い、インストール済みのアダプターとプラグインが対応する機能だけを試してください。このチェックリストは任意です。診断がこれらの操作を自動実行することはありません。

| シナリオ ID | 確認内容 |
|---|---|
| `B2-01` | 起動/再起動し、プラットフォームと Runtime の接続、通常の返信を確認する。 |
| `B2-02` | ルートが一致する場合と一致しない場合を試す。設定している場合は Pipeline、Agent、プラグインのイベントプロセッサーを個別に確認する。 |
| `B2-03` | 設定済みのツール/プラグイン/MCP 呼び出しと返信を試し、実際の宛先と内容を自分で確認する。 |
| `B2-04` | 安全なテスト環境で実行をキャンセルするか既知の不具合を再現し、その後も Bot を利用できることを確認する。 |
| `B2-05` | 対応している場合はストリーミングと対話コールバックを試し、部分的な返信、タイムアウト、再開動作を確認する。 |
| `B2-06` | 診断設定を確認する場合は無効化して再起動し、Bot の通常利用を確認する。保守担当者は別途、新規診断リクエストがないことと未送信記録の消去を確認できる。 |

診断サンプルを作るためだけに、本番のユーザー/データを退出、ミュート、削除、変更しないでください。報告にはシナリオ ID、正確な Core/SDK バージョン、プラットフォーム、おおよその UTC 時刻、期待した動作と実際の動作、実プラットフォームか WebUI デバッグかを記載してください。手動で送るログやスクリーンショットからは秘密情報と個人情報を除いてください。修正後は新しいビルドで同じシナリオを再確認します。診断のカバレッジはこれらの確認を補助するもので、代替するものではありません。
